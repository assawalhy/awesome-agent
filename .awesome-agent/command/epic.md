# /epic

Create a new epic for a substantial feature or goal, then build it — per the
**awesome-plan** skill.

1. Interview the user first: goal, approach, risks, edge cases, and what "done"
   means. Do the research before the interview — check code, docs, and prior
   epics so you don't ask what you can find yourself; challenge the goal and
   surface tradeoffs/risks instead of blindly agreeing. If planning would shift
   from the original ask (tradeoff, scope, approach), name the shift and get
   confirmation. Then run the skill's research → plan → approval loop. No
   implementation code until the user replies `go`.
2. Review existing work in the repo for relevant context and conflicts before
   building.
